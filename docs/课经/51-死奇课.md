# 51 死奇课

## 一、冻结结论

1. 死奇课的正式 matcher 严格定义为：

   ```text
   sanchuan0 === 4 (天罡 / 辰)
   AND
   4 ∈ { sike[1], sike[3], sike[5], sike[7] }
   ```

2. 不得退化为「天罡加日干或日支发用」（《图解六壬大全》过窄版本）。

3. 不得简化为「辰发用」即可（必须同时是四课上神之一，否则不能排除特殊九宗门的初传不来自四课）。

4. 「日鬼」「日墓」「灾煞」「劫煞」「恶煞相并克贼」「德」「合」「相生」「吉将的精确集合」「六处有冲克救神」「日奇」「月奇」「刑奇」本轮全部进入 `uncovered`，不参与正式 matcher 与 judgments。

5. 「三死课」的组合公式（需日、辰、岁中哪些同时成立）尚未冻结，本轮只分别给出「临日」「临辰」「临岁」三项 judgment，不输出「三死课」标签。

6. 「死奇回光」不是独立六十四课；本轮只实现《大全》原文最明确的一条：

   ```text
   死奇成立 AND yuejiang === 4
   => judgment: 死奇回光
   ```

   《订讹》「天罡太阴同见」扩展「死奇回光」尚未冻结，不实现。

7. 孟仲季判断只进入 judgment（忧二亲 / 忧己身 / 忧妻奴），不进入 matcher。

## 二、《六壬大全》正文（节录）

> 凡斗罡系日辰阴阳发用，为死奇课。斗罡者辰也……如罡加四课之神，主死亡奇怪之事，故名死奇。

> 及乘白虎，为必死之兆，大凶。

> 更临岁月之上，为三死课；天罡临日，旬内忧；临辰，月内忧；临岁，岁内忧。

> 孟忧二亲，仲忧己身，季忧妻奴。

> 辰为月将尤美，为死奇回光，除祸为福。

## 三、象曰（卦体：未济 ䷿）

> 辰为天罡，刑狱之曜。
> 疾病死期，征战凶兆。
> 论讼被囚，干贵失靠。
> 婚嫁出行，祸患自招。

象曰只采用古籍正文，不掺入程序解释。

## 四、「日辰阴阳」术语解释

「日辰阴阳」即四课，按《大全》正文四课排列为：

| 课序 | 术语     | sike 索引（上神） | 含义                |
| ---- | -------- | ----------------- | ------------------- |
| 第一课 | 日阳   | sike[1]           | 日干寄宫位上的天盘  |
| 第二课 | 日阴   | sike[3]           | 日干阳位下神位上的天盘 |
| 第三课 | 辰阳   | sike[5]           | 日支位上的天盘      |
| 第四课 | 辰阴   | sike[7]           | 日支阳位下神位上的天盘 |

四课上神即 sike[1]、sike[3]、sike[5]、sike[7]，下神为 sike[0]、sike[2]、sike[4]、sike[6]。

天罡发用并加四课之一，正是「斗罡系日辰阴阳发用」的直译。

## 五、四条路线

死奇课正式 matcher 的四条路线必须**全部允许**，不得只允许第一、第三课：

```text
第一课（sike[1] = 辰）：日阳
第二课（sike[3] = 辰）：日阴
第三课（sike[5] = 辰）：辰阳
第四课（sike[7] = 辰）：辰阴
```

实现位置：`app/Domain/Pan/Rules/SiqiRule.php` 的 `match()` 方法。

证据记录：每条命中路线在 `evidence['routes']` 列表中独立保留，结构为：

```php
[
    'lesson' => 1 | 2 | 3 | 4,
    'polarity' => '日阳' | '日阴' | '辰阳' | '辰阴',
]
```

如四课存在重复，辰同时出现在多个上神位置，**全部**记录在 `routes`，不只取第一个。

## 六、《图解六壬大全》为什么过窄

《图解六壬大全》将死奇课缩窄为「天罡加日干或日支发用」，对应日干寄宫、日支本身。

- 日干寄宫只覆盖四课中的第一课。
- 日支只覆盖四课中的第三课。
- 这种解释在《订讹》与《心镜》中也有异议。

按《大全》正文「日辰阴阳发用」，必须包括日阴与辰阴（即第二课与第四课）。本轮选择按《大全》正文严格口径实现，不退化为《图解六壬大全》版本。

## 七、《订讹》为什么不能直接简化成「辰发用」

《订讹》主张「天罡加四课发用」，与《大全》正文一致；但若简化为「初传为辰」即可，则漏掉「罡必须为四课上神」这一前提。

九宗门中：

- 伏吟、别责、八专等特殊门类的初传并非来自四课；
- 杂课中也有初传直接由地盘、阴神、变神推出的情况。

因此只有同时满足「初传为辰」与「辰为四课上神之一」，才能严格冻结死奇课。

## 九、最终 matcher

```php
$initial = $facts->get('sanchuan0');
$sike = $facts->get('sike');
$tianpan = $facts->get('tianpan');

if ($initial !== 4) {
    return null;
}

$upperBranches = [
    1 => $sike[1] ?? null,
    3 => $sike[3] ?? null,
    5 => $sike[5] ?? null,
    7 => $sike[7] ?? null,
];

$routeIndexes = [];
foreach ($upperBranches as $idx => $value) {
    if ($value === 4) {
        $routeIndexes[] = $idx;
    }
}

if ($routeIndexes === []) {
    return null;
}

$gangGround = $facts->heavenBranchGroundPosition(4);
if ($gangGround === null) {
    return null;
}
```

匹配流程：

1. `sanchuan0 === 4`（天罡发用）；
2. 至少一个上神位置是辰（四课之一含辰）；
3. 天地盘必须能求到辰所临地盘（程序完备性，不影响判定）；
4. 全部通过时构造 `RuleMatch`，包含 evidence（`initial` / `routes` / `gang_ground` / `judgments` / `uncovered`）。

## 十、天罡所临地盘算法

不能从四课下神猜测天罡临地盘，必须按天地盘：

```php
$gangGround = array_search(4, $tianpan, true);
```

`$tianpan[地盘] = 天盘支`，所以 `$gangGround` 就是天盘辰实际所临的地盘支。

实现位置：`PanFacts::heavenBranchGroundPosition(int $heavenBranch): ?int` 已经提供该 helper。

## 十一、judgments

### 1. 初传天罡乘白虎

```text
generalRidingBranch(4) === 7（白虎）
=> judgment: 天罡乘白虎
```

《大全》：「及乘白虎，为必死之兆，大凶」。

### 2. 天罡临日、临辰、临岁

```text
gangGround === stemLodgingBranch(rigan)   => 天罡临日（旬内忧）
gangGround === rizhi                       => 天罡临辰（月内忧）
gangGround === nianzhi                     => 天罡临岁（岁内忧）
```

三项分别判断；同一盘若因干支位重合同时满足两项或三项，**全部**记录，不互斥。

### 3. 孟仲季

```text
孟 = [2, 5, 8, 11]（寅巳申亥）=> 忧二亲
仲 = [0, 3, 6, 9]（子卯午酉）=> 忧己身
季 = [1, 4, 7, 10]（丑辰未戌）=> 忧妻奴
```

只进入 judgment，不进 matcher。

### 4. 死奇回光

```text
yuejiang === 4
=> judgment: 死奇回光（auspicious）
```

《大全》：「辰为月将尤美，为死奇回光，除祸为福」。

不是独立六十四课 Rule，不创建 `SiqiHuiguangRule`。

## 十二、「三死课」为何暂不冻结组合公式

《大全》原文：

> 更临岁月之上，为三死课；天罡临日，旬内忧；临辰，月内忧；临岁，岁内忧。

此处「三死课」紧接「更临岁月之上」一句，但「岁月之上」具体指日、辰、岁中哪几位的同位组合，正文未明确。本轮已分别独立判断：

- 临日 judgment：实现
- 临辰 judgment：实现
- 临岁 judgment：实现

但**不**输出「三死课」标签，文档与 uncovered 共同说明该组合语义待后续校勘。

## 十三、古籍课例

《六壬大全》正文示例：

> 甲子日、丑时、巳将，辰加子为用。三传辰、申、子。

现代生产算法对此课例的复现要点：

- 公历日期必须落在秋分到霜降节气段，使月将 = 辰。
- 甲子日、丑时的具体年份需另行校核。
- 因现代生产算法的九宗门取传与古籍偶有差异（如别责 / 八专触发），本轮不强求逐位一致；保留为「古籍原文参考盘」状态。
