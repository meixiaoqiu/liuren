# 52 灾厄课

## 一、冻结结论

1. 灾厄课的正式 matcher 严格定义为「九神煞 OR」：

   ```text
   sanchuan0 ∈ { sangche, youhun, fuyang, bingfu, sangmen, diaoke, sanqiu, wumu, suihu }
   ```

   其中：

   - 月神：丧车、游魂、伏殃；
   - 岁神：病符、丧门、吊客、岁虎；
   - 季煞：三丘、五墓。

2. 不要求克日干、克日支、克年命、乘白虎；这些都是现代《图解》一类资料的扩大口径，本项目不采用。

3. 「丧吊」二字按《六壬大全》主体定义拆为「丧门 OR 吊客」；「丘墓」拆为「三丘 OR 五墓」。重叠命中必须全部保留（例：亥年正月初传未同时命中丧车、五墓、岁虎三路）。

4. 月神基准严格使用 `yuezhi`（月建地支），不使用 `yuejiang`。岁神基准严格使用 `nianzhi`（太岁地支），不使用本命或行年。

5. 三丘五墓按 `yuezhi` 所属季节查表，不使用日干墓，也不进入 `PanFacts::seasonalPeriod()` 的「四季土旺十八日」。

6. 九个神煞的精确算法统一在 `App\Domain\Pan\Shensha\ZaieShensha`，`ZaieRule` 与 `QuickReferenceCatalog` 都必须从这里读取数据。

7. 象曰（卦体：归妹 ䷵）只采用古籍正文，不掺入程序解释。

8. 「病符临支克支」「病符并天鬼」「病符并白虎」「丧吊全加支干」「丧吊临年命、发用」「死气」「绝神」「白虎临身」「吊客入宅」「旬虎」「丘墓并虎雀丧门」「季神逢丁」「血支」「血忌」「天医、地医」等附加条件本轮**未冻结**，全部进入 `uncovered`；不得反向加入基础 matcher。

9. **高命中率不是修改古籍规则的理由。** 2026 全年 4380 盘实际命中 2639 盘（60.25%），与研究阶段预估的 60% 量级一致；本项目不动规则来凑数。

## 二、《六壬大全·灾厄课》主体定义

> 凡丧车、游魂、伏殃、病符、丧吊、丘墓、岁虎发用者，为灾厄课也。

「丧吊」即丧门、吊客；「丘墓」即三丘、五墓。整句等同于：

> 丧车、游魂、伏殃、病符、丧门、吊客、三丘、五墓、岁虎，**任一**发用者，为灾厄课也。

## 三、象曰（卦体：归妹 ䷵）

> 家门厄会，妖孽为害。疾病死亡，财喜破坏。婚孕多凶，征战大败。行人不归，访人不在。

象曰只采用古籍正文（Chinese Text Project《六壬大全·卷九》灾厄课），不掺入程序解释。

## 五、同名神煞异法风险

《六壬大全》其他章节与其他古籍存在多套同名神煞公式。本类**只**采用正文定义：

- **丧车**：「正月起未，逆行四季」是《灾厄课》正文自己的公式。其它六壬资料中可能以「丧车」指行年干前一位等异法，本类不并入。
- **游魂**：本类采用《灾厄课》正文"正月亥顺行十二辰"。其它资料可能以游魂指日支后六辰，本类不并入。
- **伏殃**：本类采用《灾厄课》正文"正月酉逆行四仲"，别名"天鬼煞"。其它资料可能以伏殃指年支后一位等异法，本类不并入。
- **三丘五墓**：本类采用季节表，不使用日干墓（金丑木未火戌水土辰）。
- **岁虎**：本类采用"岁后四辰"。

## 六、为什么不采用《图解》扩大口径

现代《图解六壬大全》将灾厄课改为"泛凶煞发用并克干支年命"的口径。如果按此口径实现：

1. 灾厄课将与"煞"+"克"两个条件耦合，命中数显著降低；
2. 与《六壬大全》正文主体定义不同；
3. 与同书其它「凶煞发用」课目（魄化、三阴、淫泆等）的判别边界不清。

本项目**冻结**《大全》正文主体定义，不采用《图解》口径。

## 七、为什么不采用日干墓的「五墓」

《六壬大全·六壬大全》后文也提到"五墓者金丑木未火戌水土辰"（按日干取墓）。若按此口径，五墓会随日干变化，与「灾厄课」主体定义中"五墓发用"作为月令季煞的位置冲突。

正文主体定义中"丘墓"是与"丧吊"并列的月令季煞，而"金丑木未火戌水土辰"明确属于日干墓系统。两者不可混用。本项目**只**采用季煞口径。

## 九、judgments

灾厄课主体不进入 judgments，理由是：

- 灾厄课的九种神煞本身已是凶煞，发用即成立课，不存在主体吉凶判断；
- 后续"病符临支克支""病符并白虎""死气""绝神"等附加条件本轮**未冻结**，不得作为 judgments 加入。

## 十一、正文古例复原

《六壬大全·灾厄课》正文示例：

```text
亥年
正月
乙亥日
卯时

初传未
```

正文另给出关键天将细节：

```text
未……加亥，乘虎
```

即"初传未加临地盘亥，且初传乘白虎"。

验证算法：

```text
正月丧车 = 未
亥年岁虎 = 未
初传 = 未
初传天将 = 白虎
```

即同一盘面同时由"月神丧车"与"岁神岁虎"两路命中灾厄课，且初传所乘天将为白虎。

复现策略：

- 扫描真实生产盘，找到同时满足以下条件的时间点：
  - nianzhi = 11（亥年）
  - yuezhi = 2（正月）
  - rigan = 1, rizhi = 11（乙亥日）
  - shizhi = 3（卯时）
  - sanchuan0 = 7（未）
  - sanchuan0tianjiang = 7（白虎）
- 生产 `PanCalculator` 使用 PHP `date_sun_info()` 按北京经纬度（纬度 39.9042、经度 116.4074、固定 UTC+8 时区）计算当日日出、日落，并据此划分昼夜贵。1923-03-03 当日卯时前半（05:00 - 06:46）落在夜贵区，初传未乘天后（11）；卯时后半（06:47 - 06:59）落在昼贵区后初传未乘白虎（7）。
- 06:47 是生产算法按 `date_sun_info()` 算出当日日出后，分钟粒度下首个进入昼贵区的时间点；这是按当前算法分钟输入下的边界值，不应理解为经独立天文资料校验后的精确历史日出时刻。
- 候选时间：1923-03-03 06:47-06:59；1911-03-06、1935-02-28、1947-02-25、1959-02-22 等需在卯时后半段验证，目前 1923-03-03 06:47 已完整复现三路命中 + 乘白虎。
- KeJingCatalog 当前选用 `1923-03-03T06:47`。

完整 3 路命中（丧车 + 五墓 + 岁虎），与正文"丧车 + 岁虎"重叠一致；初传乘白虎，与《大全》"未……加亥，乘虎"完整对应。

## 十三、多神煞同支处理

例如亥年正月乙亥日卯时初传未：

- 寅月：丧车=未、五墓=未；
- 亥年：岁虎=未；
- 三个 key 共享同一地支。

`ZaieRule::match()` 必须**全部保留**这三条命中，并在 `evidence['matched_keys']` 和 `foundations` 中按 `ZaieShensha::orderedKeys()` 顺序记录：

```text
['sangche', 'wumu', 'suihu']
```

不得在找到第一个匹配后停止。
