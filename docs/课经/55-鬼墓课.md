# 55 鬼墓课

## 一、冻结结论

正式采用候选 A：三条入口并列 OR，不要求「鬼 AND 墓」同时成立。

```text
鬼墓课成立：
    初传属于日鬼
    OR 初传等于日干五行墓
    OR 初传等于日支五行墓
```

布尔公式：

```text
initial = sanchuan0

match =
    initial IN dayGhosts(rigan)
    OR initial === stemElementTomb(rigan)
    OR initial === branchElementTomb(rizhi)
```

`matched_routes` 允许一盘同时出现多个：`day_ghost`、`stem_tomb`、`branch_tomb`。
`ghost_tomb_combined` 是增强判断（初传同时是日鬼与日干墓或日支墓），不影响主体成课。

## 二、《六壬大全》正文

本课首段定义：

> 鬼墓者，墓神覆日，或日鬼发用也。

后段细化：

> 鬼者，己日见亥之类，名为日鬼；墓者，五行墓神也。占课有鬼有墓，即为鬼墓卦。

> 统困卦之体，乃守己待时课也。

《象曰》：

> 五行克贼，死墓之乡。人丁多耗，家宅不昌。行人可至，病者颠狂。谋为迟滞，捕盗深藏。

## 三、《象曰》

直接采用本课《象曰》原文，不混入现代解释：

> 五行克贼，死墓之乡。人丁多耗，家宅不昌。行人可至，病者颠狂。谋为迟滞，捕盗深藏。

## 四、正文课例

正文壬日辰发用的典型结构：

> 壬日辰发用者，辰为壬日鬼，亦为壬水之墓，谓鬼墓兼见。

本节另含「鬼入传」「传墓」等结构示例，这些是说明三类入口如何发生，不构成独立成课条件。

## 五、墓法原文及五行墓表

正文只规定「五行墓神」并以五行墓覆盖所有日干日支。程序采用以下五行墓表（与 `YangjiuRule::STEM_ELEMENT_TOMBS` 完全一致）：

| 五行 | 墓 |
| --- | --- |
| 木 | 未 |
| 火 | 戌 |
| 土 | 辰 |
| 金 | 丑 |
| 水 | 辰 |

日干墓索引（与项目其他规则共用）：

```php
[0 => 7, 1 => 7, 2 => 10, 3 => 10, 4 => 4, 5 => 4, 6 => 1, 7 => 1, 8 => 4, 9 => 4];
// 甲未 乙未 丙戌 丁戌 戊辰 己辰 庚丑 辛丑 壬辰 癸辰
```

十二支五行墓：

```php
[
    0 => 4,   // 子水 -> 辰
    1 => 4,   // 丑土 -> 辰
    2 => 7,   // 寅木 -> 未
    3 => 7,   // 卯木 -> 未
    4 => 4,   // 辰土 -> 辰
    5 => 10,  // 巳火 -> 戌
    6 => 10,  // 午火 -> 戌
    7 => 4,   // 未土 -> 辰
    8 => 1,   // 申金 -> 丑
    9 => 1,   // 酉金 -> 丑
    10 => 4,  // 戌土 -> 辰
    11 => 4,  // 亥水 -> 辰
];
```

不采用十干十二长生墓。Unit 测试 `branch tomb locks for the four cardinal branches` 与 `each stem tomb...is locked against the ten stem tomb` 锁定了五行墓表与十干十二长生墓表的差异。

## 六、日鬼原文及日鬼表

正文明确给出同性相克的日鬼表（壬癸各两位），程序不得用普通五行相克直接推导。

```text
甲 → 申
乙 → 酉
丙 → 子
丁 → 亥
戊 → 寅
己 → 卯
庚 → 午
辛 → 巳
壬 → 辰、戌
癸 → 丑、未
```

按项目索引（地支 0..11：子丑寅卯辰巳午未申酉戌亥）：

```php
[
    0 => [8],      // 甲 -> 申
    1 => [9],      // 乙 -> 酉
    2 => [0],      // 丙 -> 子
    3 => [11],     // 丁 -> 亥
    4 => [2],      // 戊 -> 寅
    5 => [3],      // 己 -> 卯
    6 => [6],      // 庚 -> 午
    7 => [5],      // 辛 -> 巳
    8 => [4, 10],  // 壬 -> 辰、戌
    9 => [1, 7],   // 癸 -> 丑、未
];
```

「异阴阳但五行相克」的反例覆盖：壬日丑（异阴阳土克水）、壬日未（异阴阳土克水）、癸日辰（异阴阳土克水）、癸日戌（异阴阳土克水）、甲日寅、甲日巳、丙日午、庚日子等案例均不应进入 `day_ghost` 路线。Unit 测试 `same element but wrong yin-yang branch is not a day ghost` 锁定了这一边界。

## 七、《订讹》严格解释

《订讹》提出更严格解释：

> 凡干支上神发用，兼为鬼墓，方成鬼墓课。若仅发用而不兼鬼墓，不得名鬼墓。

并提到「支鬼支墓」路线：

> 支鬼者，支上神克日支也；支墓者，支上神为支墓也。

## 八、正文与《订讹》的差异

| 解释 | 是否要求「鬼 AND 墓」 | 是否要求干支上神发用 | 是否要求支鬼 |
| --- | --- | --- | --- |
| 《六壬大全》正文 | 否（任一即可） | 否 | 否 |
| 《订讹》 | 是 | 是 | 是 |

正文宽而《订讹》严。本课正式 matcher 采用正文宽解释。理由：

1. 正文「鬼者……墓者……」以分号并列说明，并不强制 AND；
2. 「壬日辰发用者，辰为壬日鬼亦为壬水之墓，谓鬼墓兼见」是正文对「鬼墓兼见」的专门表述，说明「鬼墓兼见」是结构性加强条件，不是成课必要条件；
3. 项目当前原则是不让后世注解静默删掉正文明确包含的成立范围；
4. 「支鬼」目前没有可冻结的古籍程序定义。

## 九、候选规则表

| 候选 | 精确逻辑 | 评价 |
| --- | --- | --- |
| A | 初传属于日鬼 OR 初传等于日干五行墓 OR 初传等于日支五行墓 | 正式采用；正文三条入口并列 OR |
| B | 初传同时是日鬼与（干墓或支墓） | 《订讹》字面严格解释；排除「仅鬼」「仅墓」盘面 |
| C | 初传是日鬼或日干墓或日支墓 AND 干上神或支上神为鬼或墓 | 进一步收紧；无独立课例 |
| D | 初传是日鬼或日干墓或日支墓 AND 同时为「支鬼」 | 需要支鬼定义，尚未冻结 |

## 十、为何不采用「鬼 AND 墓」

若把 matcher 收紧为「鬼 AND 墓」，则「仅日鬼」「仅日干墓」「仅日支墓」三类单一入口的盘面将不计入鬼墓课。Unit 测试 `day ghost entry can independently establish the lesson` 等三条测试明确保护这三条独立入口；测试 `multiple matched routes are all preserved and ordered` 进一步保护多路线命中的 evidence 完整性。

## 十一、为何不用普通五行相克直接计算日鬼

普通「五行克日干」会把壬日的辰戌丑未四个支都视作日鬼；正文日鬼表是「同性相克」，壬日只取辰、戌。Unit 测试 `same element but wrong yin-yang branch is not a day ghost` 锁定了「异阴阳但五行相克」的反例。

## 十二、为何不实现支鬼

「支鬼」在《订讹》中以「支上神克日支」一笔带过，但本项目缺少可冻结的日支神煞表与稳定程序定义。若用「某支五行克日支」直接套用，会同时把日支墓支本身视作支鬼，逻辑不自洽。本任务仅记录在 `uncovered`，不并入 matcher。

## 十三、正式 matcher

```text
is_guimu =

```

## 十四、judgments

只实现一个高置信度增强判断：

- `ghost_tomb_combined`：初传同时是日鬼与日干墓或日支墓。前台显示「鬼墓兼见（鬼墓俱见）」。不成立不影响鬼墓课主体。

辅助：

- `multi_route_matched`：当一盘同时命中两条或三条入口时，给出「多路线同时命中」汇总，便于前台展示。

## 十五、古籍课例复原

《六壬大全》正文壬日辰发用结构。Unit 与 Catalog 中通过 `2026-01-08 15:00`（壬午日、申时、丑将）真实复现：

- 日干壬，正文日鬼为辰、戌；
- 日干壬属水，五行墓在辰；
- 初传辰同时是日鬼与日干墓，命中「鬼墓兼见」。

古籍原文未给现代年月日时，本节只能给出与原文结构等价的现代真实盘面，不伪造时间。

## 十八、未实现项

以下内容记录到 `uncovered`：

- 《订讹》「支鬼支墓」路线的支鬼，缺稳定古籍程序定义；
- 鬼在日上发用、墓门开格、蛇虎与墓神组合、卯酉位置组合等加强条件；
- 辰未日墓、丑戌夜墓、辰戌刚猛急速、丑未迟延柔缓等昼夜墓吉凶；
- 财、禄、官星、长生发用后中末见墓与日鬼盗气而中末逢墓等后续结构；
- 鬼墓有克制、冲破后的反凶为吉、传墓入墓、自墓传生、干支乘墓坐墓互换坐墓、干墓临支、墓神覆日等结构。

## 十九、重新评估条件

若出现：

- 可校验的早期版本明确把「鬼 AND 墓」列为成课必要条件，并有第二课例或跨文献一致旁证；
- 支鬼取得稳定古籍程序定义（明确日支神煞表与计算方法）；
- 墓法取得稳定十干十二长生墓表，并明确「五行墓」与「十干墓」分用条件；

应重新评估 B、C、D，并相应更新 boundary 测试与统计脚本。

当前选择 A 的理由是：正文三条入口并列 OR，壬日辰发用是「鬼墓兼见」结构性增强，不是成课必要条件；《订讹》支鬼没有可冻结定义；十干十二长生墓与五行墓是不同体系，本课正文只规定五行墓。
