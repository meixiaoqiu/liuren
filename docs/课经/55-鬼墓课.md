# 55 鬼墓课

## 一、冻结结论

正式 matcher 选 A'：日鬼发用，且初传同时为日干墓或日支墓。

```text
鬼墓课成立：
    初传 ∈ dayGhosts(rigan)
    AND
    (初传 === stemElementTomb(rigan) OR 初传 === branchElementTomb(rizhi))
```

布尔公式：

```text
is_guimu =
    in_array(initial, DAY_GHOSTS[rigan], true)
    AND (initial === STEM_ELEMENT_TOMBS[rigan] OR initial === BRANCH_ELEMENT_TOMBS[rizhi])
```

`matched_routes` 允许一盘同时出现多个：`day_ghost`、`stem_tomb`、`branch_tomb`。A' 下命中本课必然包含 `day_ghost`，并至少再包含 `stem_tomb` 或 `branch_tomb` 之一。`ghost_tomb_combined` 不再是可选增强，而是主体命中的必要条件之一。

## 二、《六壬大全》正文

本课首段定义（识典古籍《六壬大全》卷八「鬼墓」条可核验）：

> 凡日辰墓神及日鬼发用，为鬼墓课。

随后细化：

> 五行受鬼克贼，又加四墓，故名鬼墓。

> 统困卦之体，乃守己待时课也。

「日辰」在六壬语境中即日干与日支；本程序把「日辰墓神」程序化为「日干五行墓 OR 日支五行墓」。

## 三、《象曰》

直接采用本课《象曰》原文，不混入现代解释：

> 五行克贼，死墓之乡。人丁多耗，家宅不昌。行人可至，病者颠狂。谋为迟滞，捕盗深藏。

## 四、正文课例

正文课例：

> 如壬申日丑时午将，壬日属水，以辰为墓，又为日鬼，加日发用，为鬼墓。

《订讹》例：

> 假如壬日辰加亥发用，既作日鬼，又作日墓，故名鬼墓。

程序复现：`2026-01-08 15:00`，壬午日辰发用，复现「日鬼 + 日干墓」结构；此现代盘只作程序验证，不冒充古籍课例原盘。

## 五、墓法原文及五行墓表

正文只规定「五行墓神」并以五行墓覆盖所有日干日支。程序采用以下五行墓表（与 `YangjiuRule::STEM_ELEMENT_TOMBS` 完全一致）：

| 五行 | 墓 |
| --- | --- |
| 木 | 未 |
| 火 | 戌 |
| 土 | 辰 |
| 金 | 丑 |
| 水 | 辰 |

日干墓索引（与项目其他规则共用）：

```php
[0 => 7, 1 => 7, 2 => 10, 3 => 10, 4 => 4, 5 => 4, 6 => 1, 7 => 1, 8 => 4, 9 => 4];
// 甲未 乙未 丙戌 丁戌 戊辰 己辰 庚丑 辛丑 壬辰 癸辰
```

十二支五行墓：

```php
[
    0 => 4,   // 子水 -> 辰
    1 => 4,   // 丑土 -> 辰
    2 => 7,   // 寅木 -> 未
    3 => 7,   // 卯木 -> 未
    4 => 4,   // 辰土 -> 辰
    5 => 10,  // 巳火 -> 戌
    6 => 10,  // 午火 -> 戌
    7 => 4,   // 未土 -> 辰
    8 => 1,   // 申金 -> 丑
    9 => 1,   // 酉金 -> 丑
    10 => 4,  // 戌土 -> 辰
    11 => 4,  // 亥水 -> 辰
];
```

不采用十干十二长生墓。Unit 测试 `branch element tombs are locked for the four cardinal branches` 与 `each stem element tomb is locked against the ten-stem lifecycle tomb` 直接锁定五行墓表，并验证其与十干十二长生墓表的差异。

## 六、日鬼原文及日鬼表

《六壬大全》本课以「己日卯」「甲日申」一类列举明确给出同性相克的日鬼表（壬癸各两位），程序不得用普通五行相克直接推导。

```text
甲 → 申
乙 → 酉
丙 → 子
丁 → 亥
戊 → 寅
己 → 卯
庚 → 午
辛 → 巳
壬 → 辰、戌
癸 → 丑、未
```

按项目索引（地支 0..11：子丑寅卯辰巳午未申酉戌亥）：

```php
[
    0 => [8],      // 甲 -> 申
    1 => [9],      // 乙 -> 酉
    2 => [0],      // 丙 -> 子
    3 => [11],     // 丁 -> 亥
    4 => [2],      // 戊 -> 寅
    5 => [3],      // 己 -> 卯
    6 => [6],      // 庚 -> 午
    7 => [5],      // 辛 -> 巳
    8 => [4, 10],  // 壬 -> 辰、戌
    9 => [1, 7],   // 癸 -> 丑、未
];
```

「异阴阳但五行相克」的反例覆盖：壬日丑（异阴阳土克水）、壬日未（异阴阳土克水）、癸日戌（异阴阳土克水）、甲日寅、甲日巳、丙日午、庚日子等案例均不应进入 `day_ghost` 路线。Unit 测试 `same element but wrong yin-yang branch is not a day ghost` 锁定了这一边界。

## 七、《订讹》严格解释（原文）

《订讹》对本课的按语（可核验《六壬大全》卷八同条附按）原文为：

> 鬼墓：干支上神发用，或作干鬼干墓，或作支鬼支墓。假如壬日辰加亥发用，既作日鬼，又作日墓，故名鬼墓。

《订讹》的两条路线是「干鬼 + 干墓」或「支鬼 + 支墓」，并且要求「干支上神发用」。它支持「鬼与墓同时具备」这一大方向，但不能把「支鬼支墓」改写为程序中的 `day_ghost + branch_tomb`；这些更严格语义没有全部进入正式 matcher。

## 八、正文与《订讹》的差异

| 解释 | 是否要求鬼 + 墓 | 入口形态 |
| --- | --- | --- |
| 《六壬大全》正文 | 是 | 「日辰墓神及日鬼发用」 |
| 《订讹》按语 | 是 | 干支上神发用；干鬼 + 干墓，或支鬼 + 支墓 |
| 本程序 A' | 是 | 日鬼 ∧ (日干墓 ∨ 日支墓) |

研究关系为：《六壬大全》正文经本项目解释为「日鬼 AND（日干墓 OR 日支墓）」，据此决定正式 matcher A'。《订讹》支持「鬼与墓同时具备」这一大方向，但另有限定干支上神发用，并存在尚未程序化的「支鬼支墓」路线。因此 A' 不与《订讹》的完整语义等同。

## 九、候选规则表

| 候选 | 精确逻辑 | 评价 |
| --- | --- | --- |
| 旧 OR（已被推翻） | 初传 ∈ 日鬼 ∨ 初传 = 日干墓 ∨ 初传 = 日支墓 | 与「五行受鬼克贼，又加四墓」矛盾；27.78% 命中率对专名课异常 |
| A' | 初传 ∈ 日鬼 ∧ (初传 = 日干墓 ∨ 初传 = 日支墓) | **正式采用**；源于本项目对正文的程序解释，《订讹》仅支持鬼墓兼具的大方向 |
| A'' | 初传 ∈ 日鬼 ∧ 初传 = 日干墓 | 无依据地删除支墓路线 |
| B | 初传 ∈ 日鬼 ∧ 初传 = 日干墓 ∧ 初传 = 日支墓 | 比 A' 更严，但 720 中只有 3 课，命中率过低，无原文支撑 |
| C | 干上神或支上神发用并兼为鬼墓 | 进一步收紧；非本课要求 |

## 十、为何不采用「鬼 OR 墓」

旧 OR 版本在 720 中命中 200 课（27.78%）。这种命中率对六十四课专名课是不正常的；正文「五行受鬼克贼，又加四墓，故名鬼墓」明确把鬼、墓同时具备作为命名根据，A' 720 命中 13 课（约 1.81%），与其他课经口径相符。

## 十一、为何不用普通五行相克直接计算日鬼

普通「五行克日干」会把壬日的辰戌丑未四个支都视作日鬼；正文日鬼表是「同性相克」，壬日只取辰、戌。Unit 测试 `same element but wrong yin-yang branch is not a day ghost` 锁定了「异阴阳但五行相克」的反例。

## 十二、为何不实现支鬼

《订讹》给出「支鬼支墓」一句，但「支鬼」的具体古籍程序定义（「支上神克日支」的精确计算、是否需满足某些附加条件）尚未冻结。若用「某支五行克日支」直接套用，会同时把日支墓支本身视作支鬼，逻辑不自洽。本任务仅记录在 `uncovered`，不并入 matcher。

## 十三、正式 matcher

```text
is_guimu =
    in_array(initial, DAY_GHOSTS[rigan], true)
    AND (initial === STEM_ELEMENT_TOMBS[rigan] OR initial === BRANCH_ELEMENT_TOMBS[rizhi])
```

## 十四、主体与附加判断

A' 下「鬼墓兼见」不是增强，而是主体命中的必要条件：

- `ghost_tomb_combined`：放在 `foundations` / 主体判断。日鬼 + 日干墓可引用《订讹》「既作日鬼，又作日墓」；日鬼 + 日支墓只引用《六壬大全》主定义，并说明它是本项目对「日辰墓神」采用 A' 的程序解释；三者同时可展示两类证据。
- `triple_ghost_and_tombs`：保留在 `judgments` / 附加判断，初传同时为日鬼、日干墓与日支墓时显示「鬼墓三方兼见」。

## 十五、古籍课例复原

《六壬大全》正文课例是「壬申日丑时午将」；《订讹》另举「壬日辰加亥发用」。Unit 与 Catalog 中的 `2026-01-08 15:00`（壬午日、申时、丑将）是程序复现，三层不混同。该盘结构为：

- 日干壬，正文日鬼为辰、戌；
- 日干壬属水，五行墓在辰；
- 初传辰同时是日鬼与日干墓，对应《订讹》「既作日鬼，又作日墓」。

古籍原文未给现代年月日时，本节只能给出与原文结构等价的现代真实盘面，不伪造时间。

## 十八、未实现项

以下内容记录到 `uncovered`：

- 《订讹》「支鬼支墓」路线的支鬼，缺稳定古籍程序定义；
- 鬼在日上发用、墓门开格、蛇虎与墓神组合、卯酉位置组合等加强条件；
- 辰未日墓、丑戌夜墓、辰戌刚猛急速、丑未迟延柔缓等昼夜墓吉凶；
- 财、禄、官星、长生发用后中末见墓与日鬼盗气而中末逢墓等后续结构；
- 鬼墓有克制、冲破后的反凶为吉、传墓入墓、自墓传生、干支乘墓坐墓互换坐墓、干墓临支、墓神覆日等结构。

## 十九、重新评估条件

若出现：

- 古籍第二手材料明确反对「鬼与墓同时具备」为本课必要条件，并有第二课例或跨文献一致旁证；
- 支鬼取得稳定古籍程序定义（明确日支神煞表与计算方法）；
- 墓法取得稳定十干十二长生墓表，并明确「五行墓」与「十干墓」分用条件；

应重新评估 A'、A''、B，并相应更新 boundary 测试与统计脚本。

当前选择 A' 的理由是：本项目把正文「日辰墓神及日鬼发用」解释为日鬼与日干墓或日支墓同时具备；《订讹》支持鬼墓兼具的大方向，但其干支上神发用和支鬼支墓语义未全部进入 matcher；A' 命中率 1.78%–1.81% 与六十四课专名课口径相符。
